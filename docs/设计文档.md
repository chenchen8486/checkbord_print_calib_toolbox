## 1. 目标与范围

### 1.1 目标

把 C++ 工程 `Calibrate_and_Measure` 的**功能 1（生成标定板打印文件）**和**功能 2（相机标定）**做成一套能力相同的 Python 工程，供现场制板、采图标定，并产出可被现有 C++ 测量链路（`LoadCalibrationXml` / OpenCV `FileStorage`）继续使用的标定 XML。

成功标准以已确认需求第 10 节为准，而不是“代码从 C++ 逐行翻译”。PDF 不要求与 C++ 字节级一致，但版面几何、标定数值语义、XML 字段/形状、质量门禁与对外中文 `err_msg` 必须按本文落地。

### 1.2 本阶段要做

- 工程骨架、独立虚拟环境，以及随包 `config.ini`（**仅**含 `[checkerboard]`、`[calibrate]`、`[debug]` 三段）。
- 功能 1：按 `[checkerboard]` 生成打印三件套（`checkerboard.pdf`、`checkerboard_preview.png`、`打印说明.txt`）。
- 功能 2：按 `[calibrate]`（及与制板段的缺省跟随）对 1～n 张采图求解标定，写出 XML；`[debug] save_intermediate=true` 时按规则输出 QA 质检图。
- 对外 Python 门面与现场命令行（只覆盖制板与标定）。
- 中文分级日志、中文 `err_msg`、自测与对拍口径（对拍基准数字在实现阶段跑 C++ 基线后冻结，本文不编造）。

### 1.3 明确不做

下列内容设计与实现都不得展开：

- **功能 3 图像测量**（`Measurer` / Init / SetBackground / Measure、宽高与水平边、码区、背景建模、分割、精修、旋转、测量 CSV）。
- 作为独立交付能力的正射矫正器运行时接口（对业务方暴露、按帧矫正测量图）。功能 2 **内部**为质量验证而做的正射闭环属于功能 2，见第 6.7 节。
- 读取或实现 `[rectify]`、`[paths]`、`[segmentation]`、`[ai_seg]`、`[trad_seg]`、`[refine]`、`[rotate]`、`[measure]`、`[code_detect]`、`[code_detect_ai]` 等测量相关配置段。随包 ini **不得**带这些段。
- 更改目标文件夹名称（必须保持 `checkbord_print_calib_toolbox`）。
- 改动 C++ 工程 `Calibrate_and_Measure` 的代码或配置。
- 在本设计经用户确认前编写业务代码、运行 kimi-cli、git init/commit/push。

已确认需求第 11 节 B：本阶段不增加实印、格距实测、正式条件采图和已知物理长度验收；不给 Python 工程加功能 3。本阶段验收与实现均不包含上述项。

## 3. 对外 Python 门面与命令行

### 3.1 版本

- 本工程自有版本，建议首发为 `1.0.0`，**不**要求与 C++ 门面 `2.1.4` 相同。
- `version() -> str` 返回该版本串（与 `__version__` 一致），须可查询。

### 3.2 数据结构

```python
from dataclasses import dataclass

@dataclass
class CalibReport:
    rms: float = 0.0              # RMS 重投影误差（px）
    verify_mean_px: float = 0.0   # 正射验证闭环平均残差（px）；验证未完成时为 0
    verify_p95_px: float = 0.0    # 正射验证闭环 p95 残差（px）；验证未完成时为 0
    xml_path: str = ""            # 配置解析后的绝对路径；配置成功读出后即应填写
```

字段语义与 C++ `cam::CalibReport` 对等。失败时已知字段尽量填写；验证未完成时 `verify_mean_px` / `verify_p95_px` 保持 0，**不得**把 0 当作验证达标。

### 3.3 函数签名与调用约定

```python
def version() -> str: ...

def make_board(ini_path: str) -> tuple[bool, str]:
    """返回 (ok, err_msg)。成功时 ok is True 且 err_msg 为空；失败时 ok is False 且 err_msg 为第 3.6 节中文原因。"""

def calibrate(
    board_images,          # 1～n 张内存图像，OpenCV/NumPy 数组（8 位 1/3/4 通道）
    ini_path: str,
    report: CalibReport | None = None,
) -> tuple[bool, str, CalibReport]:
    """返回 (ok, err_msg, report)。"""
```

约定：

1. 每个对外接口都以 **ini 路径** 为配置入口，显式传入，无隐式全局配置。建议调用方传绝对路径。
2. **不向调用方抛异常**。门面内部捕获 `cv2.error` / `Exception` / 其它异常，转为 `ok=False` 与中文 `err_msg`。未列出的异常兜底也必须是中文，并写明动作与原因，例如 `制板内部异常: {原因}`、`标定内部异常: {原因}`、`读取配置失败: {原因}`。
3. 成功时 `ok is True` 且 `err_msg` 为空；失败时 `ok is False` 且 `err_msg` 为固定句式（见第 3.6 节）。
4. `calibrate`：若调用方传入 `report` 对象，则就地填写，并同时作为返回值第三项；未传入则新建 `CalibReport` 返回。不得因 `report is None` 而省略摘要计算。
5. `board_images` 为空列表必须失败，文案见第 3.6 节。多张图视为**同一姿态下的连拍降噪**（相机、镜头和标定板在连拍期间都必须保持静止），不是换角度标定。

### 3.4 命令行

子命令（具体名以此为准，实现时不得再改成测量菜单）：

```text
checkbord-toolbox make-board --ini <ini路径>
checkbord-toolbox calibrate --ini <ini路径> [--image <路径> ...]
```

等价模块入口：`python -m checkbord_print_calib_toolbox …`。

| 子命令 | 行为 | 退出码 |
|---|---|---|
| `make-board` | 读取 ini，在 `out_dir` 生成三件套 | 成功 0；失败非 0，控制台打印中文原因 |
| `calibrate` | 若给出一个或多个 `--image`，按给定顺序读这些文件并标定；否则读 `[calibrate] input_dir` | **成功且质量达标** 为 0；失败（含质量门禁未过、读图失败、目录无图等）非 0。打印中文原因，并在已写出时打印 XML / QA 路径。无论成败，只要已求解，控制台都应打印 `RMS`（4 位小数）、验证 `mean` / `p95`（3 位小数），便于现场判断 |

不提供功能 3 的批量测量入口，也不提供交互式菜单。

参数非法（缺 `--ini`、未知子命令等）同样以非 0 退出，并打印中文用法说明。

### 3.5 命令行读 `input_dir` 的扫图规则

与 C++ `common::ListImages` + `RunCalibrateFromDir` 对齐：

1. 扩展名（大小写不敏感）：`.bmp`、`.png`、`.jpg`、`.jpeg`、`.tif`、`.tiff`。
2. **不递归**子目录，只扫该目录一层；只收常规文件。
3. 文件名（不含扩展名，即 stem）包含 `demo`（不区分大小写）或包含 `副本` 的条目跳过。
4. 其余命中文件按**完整路径字符串字典序**排序。Windows 上路径分隔符统一为 `\` 后再比较（对等 C++ `std::filesystem::path::string()` 在该平台的习惯）。同一目录下即按文件名排序。
5. 排序后的第一张用于 QA 与正射验证；多图角点均值也依赖该顺序。顺序变化可能影响结果，验收必须冻结顺序（见第 8.2 节）。
6. 某一张读失败：整次命令行标定失败，打印中文 `图像读取失败: {path}`，**不**跳过坏图继续，也**不**对已读入的子集求解。
7. 目录不存在或不可访问：不进入标定，提示 `标定采图目录不存在或不可访问: {dir}`。
8. 目录存在但过滤后无图：不进入标定，提示 `标定采图目录为空，请先把棋盘格采图放入: {dir}`。

读图方式见第 6.2 节（`IMREAD_UNCHANGED`，必要时 BMP 兜底）。显式 `--image` 列表保持调用方给定顺序，不再按文件名重排；其中任一路径读失败，同样整次失败并使用上述读失败文案。

### 3.6 对外 `err_msg` 固定句式

数字格式化与 C++ 现网及需求第 9 节一致：**格距/留白保留 1 位小数，RMS 保留 4 位，验证 mean 保留 3 位**。标记侵入句中的矩形数值改用最短十进制（对等 `%.6g`），以免 `2.25`、`420.15` 被一位小数抹掉。不得改成英文或改换责任描述。

**配置**

- `无法打开配置文件: {path}`
- `配置文件第 {n} 行段头格式错误: {内容}`
- `解析配置文件异常: {path}，原因: {原因}`
- `读取标定配置失败: {原因}`

**功能 1**

- `参数非法：格子边长/纸张尺寸必须为正，横纵格数必须不小于 2`
- `横向留白不足：需要至少 {border}mm，实际仅 {ox}mm`
- `纵向留白不足：需要至少 {border}mm，实际仅 {oy}mm`
- `横纵格数必须一奇一偶（当前 {cols}x{rows} 存在 180° 旋转歧义）`
- `方向标记侵入棋盘图案（标记 [{x},{y},{w},{h}]mm，图案 [{ox},{oy},{pw},{ph}]mm），请加大纸张或留白，或减小格数/格边长`
- `创建输出目录失败：{out_dir}（{系统原因}）`
- `无法创建文件：{path}`
- `写入文件失败：{path}`
- `保存预览图失败：{path}`

**功能 2**

- `无标定采图（图像列表为空），无法标定`
- `无角点集合，无法标定`
- `标定图尺寸非法`
- `内角点配置非法: {cols}x{rows}`
- `棋盘格图像格式不支持（须为 8UC1/8UC3/8UC4）`（单张门面；有意不跟 C++ 单图入口的「标定图像格式不支持…」）
- `第 {i} 张标定采图格式不支持（须为 8UC1/8UC3/8UC4）`（`{i}` 从 1 起）
- `第 {i} 张标定采图尺寸 ({w}, {h}) 与首张 ({w0}, {h0}) 不一致`
- `未检测到完整棋盘格（目标 {cols}x{rows}={n} 个内角点），请检查标定板摆放与成像`
- `第 {i} 张标定采图角点检测失败: {具体原因}`
- `棋盘格检测异常: {原因}`
- `角点亚像素细化异常: {原因}`
- `各图角点数量不一致`
- `角点数量 {n} 与内角点配置 {cols}x{rows}={expect} 不符`
- `标定求解失败: {原因}`
- `标定求解结果非法（外参缺失或 RMS 非有限值）`
- `创建标定输出目录失败: {dir}，{系统原因}`
- `标定文件写入异常: {path}，{原因}`
- `标定文件无法写入: {path}`
- `标定文件回读失败: {原因}`
- `创建 QA 目录失败: {qa_dir}，{系统原因}`
- `重投影计算失败: {原因}`
- `构建正射矫正映射失败: {原因}`
- `正射矫正输出为空`

对外最终 `err_msg`（门面 `calibrate` 与命令行退出时），在 XML 已写出并走完正射验证之后，**以总质量门禁这一句为准**：

```text
标定质量偏低：RMS {rms}px，校正验证 mean {mean或“未通过”}（标定文件已输出: {xml}[，QA 图: {qa_dir}]），请检查印刷精度与采图条件后重标
```

- `{rms}` 保留 4 位小数；验证通过时 `{mean}` 为保留 3 位小数并带 `px` 后缀（如 `0.123px`）；验证未通过时 mean 处写 `未通过`（不加 `px`）。
- `save_intermediate=false`（含缺键）时**不要**带「QA 图」片段。
- C++ `SolveAndSaveCalibration` 在 RMS 超门禁时的中间态句 `标定质量偏低：RMS {rms} px 超过 0.3 px 门禁（标定文件仍已写出: {xml}），请检查印刷精度与采图条件后重标` **只作内部中间态，不得作为对外验收对照**。走完验证后必须用总门禁句覆盖。

### 3.7 日志约定

- 格式对等 C++：`[DEBUG] …` / `[INFO] …` / `[WARN] …` / `[ERROR] …`，使用中文完整句子。
- 默认阈值 `INFO`（`DEBUG` 默认不显示）。`WARN`/`ERROR` 写 stderr，其余写 stdout。
- 提供可替换的日志钩子（例如 `set_log_handler(fn)`），集成方可改接自己的日志系统，但不因此改变对外返回值。
- 制板成功须能从日志看到三个产物的实际路径，并注明预览图「仅供核对，勿用于打印」。
- 标定过程须记录：角点检测成功与数量、多图时「角点取均值降噪」、RMS 分级结论、焦距与畸变系数、XML 路径、QA 目录（仅 debug 打开时）、质量门禁未通过时的警告。
- 未回填实测格距时，按第 4.5 节打警告日志（名义值取当前跟随的 `square_mm`，不得写死 15.0）。
- 日志是辅助信息，不能代替 `err_msg` 与退出码。

## 4. ini 解析与跟随规则

功能 1 与功能 2 共用本节实现。解析器自行实现（不引入额外 ini 库），行为与 C++ `IniFile` / `AppConfig::LoadFromIni` 对齐，并落实需求相对 C++ 的有意差异（`save_intermediate` 缺键为 false；格距告警按标称值且以“是否显式写出”判定）。

### 4.1 文件与语法

- 编码 utf-8，可带 BOM（`EF BB BF`）；解析时跳过 BOM。
- 支持 `#`、`;` **行注释和行尾注释**（先按行内首次出现的 `#` 或 `;` 截断，再修剪空白）。
- 键、值、段名两侧空白修剪。段名、键名大小写敏感，与 C++ `std::map` 精确匹配一致（出厂键一律小写）。
- 段头必须为 `[name]`，`]` 缺失或名为空则失败：`配置文件第 {n} 行段头格式错误: {内容}`。
- 位于任何段之外的键、缺少 `=` 的行、键名为空的行：记警告并忽略，不导致整体失败。
- 打不开文件：`无法打开配置文件: {path}`。其它解析异常：`解析配置文件异常: {path}，原因: {原因}`。
- 布尔值（大小写不敏感）：`1` / `true` / `yes` / `on` 为真；`0` / `false` / `no` / `off` 为假；无法解析则警告并用缺省。
- 数值解析失败或含多余字符：警告后，失败则用缺省，多余字符时仍取已解析前缀（对等 C++ `stod`/`stoi` + 警告）。
- 未知段、未知键忽略（因此即使用户误把功能 3 段拷进来，本工程也不得去实现它们）。

### 4.2 相对路径

ini 内的相对路径一律相对**该 ini 文件所在目录**解析，ini 可放在任意位置。判定绝对路径：含 `:`（如 `D:\...`），或以 `/`、`\` 开头。空路径保持为空。建议调用方传 ini 的绝对路径；若传入相对路径，先相对**进程当前工作目录**把 ini 自身定位成绝对路径，再以其父目录为基准解析内部相对路径。

本工程**不**实现 C++ 的 `FindProjectRoot`（相对 exe 上两级）旧行为。

路径类字段：`[checkerboard] out_dir`，`[calibrate] input_dir` / `out_xml` / `qa_dir`。解析完成后写入配置对象的已是绝对路径；`CalibReport.xml_path` 使用解析后的 `out_xml`。

### 4.3 缺键缺省（与 C++ 结构体出厂值一致，除非需求另有约定）

### 4.4 跟随规则与“是否显式写出”

加载顺序：先读完整 `[checkerboard]`，再读 `[calibrate]`。

- `pattern_cols` / `pattern_rows` / `square_x_mm` / `square_y_mm` 在 ini 中**未写出**时，必须跟随**当前** `[checkerboard]` 的 `cols-1`、`rows-1`、`square_mm`。显式写出则以显式值为准（即使数值碰巧等于跟随值）。
- **“显式写出”以解析后该段中是否存在该键为准**（对等 C++ `IniFile::Has`）：段内出现该键即视为显式，不论值是否等于 15.0、是否等于当前 `square_mm`。被注释掉的行不是键。不得用“数值是否等于 15.0”作为是否告警或是否跟随的判断。
- 四个键各自独立：只写其中一部分时，未写的键仍跟随，已写的键用显式值。
- 若四个跟随键中任一未写出，打一条 Info 日志（对等 C++ `LoadFromIni`）：`标定参数缺省项跟随 [checkerboard]: 内角点 {pattern_cols}x{pattern_rows}，标称格距 {square} mm`（此处 `{square}` 为当前生效的 `square_x_mm`，格式对等 `%g`）。

### 4.5 未回填实测格距的告警

仅当 `square_x_mm` **与** `square_y_mm` **均未**在 ini 中显式写出（因而都跟随 `[checkerboard] square_mm`）时，打一条 Warn：

```text
未配置实测格距，按名义 {square_mm}mm 计算；打印缩放误差将直接进入测量结果，务必实测后重标
```

`{square_mm}` 取**当前** `[checkerboard] square_mm`，保留 1 位小数。不得照搬 C++ `LoadCalibrateConfig` 里写死的「名义 15.0mm」，也不得用“数值恰好等于 15.0”决定是否告警：把制板格距改成别的合法值并保持跟随时，告警中的数字必须跟着变；显式回填实测值后，即使回填值恰好是 15.0，也不再打这条告警。只回填横或纵其中一项时，不打本条（因为“均未写出”不成立）。

### 4.6 随包 `config.ini` 内容约束

- 编码 utf-8（可带 BOM）。
- **只含** `[checkerboard]`、`[calibrate]`、`[debug]` 三段，注释可说明用途与跟随规则。
- **不要写出** `pattern_cols`、`pattern_rows`、`square_x_mm`、`square_y_mm` 四个跟随键，以免把“未实测的标称值”冻成假实测值。可用注释说明：仅当与制板段不一致或已卡尺实测时才显式配置。
- `save_intermediate = false` 须显式写出。
- `target_mm_per_px` 的注释必须写清：它改变的是物理覆盖范围和 px→mm 系数，**输出像素宽高与标定输入相同，不随该刻度改变**。不得再沿用 C++ 随包 ini 里「只影响输出图大小」的不准确说法。

出厂数值：`square_mm=15.0`，`cols=35`，`rows=28`，`border_mm=15.0`，`paper_w_mm=555.0`，`paper_h_mm=450.0`，`out_dir=assets/checkerboard`，`input_dir=assets/test_data/calibration`，`out_xml=assets/calibration/checkerboard_calib.xml`，`target_mm_per_px=0.136`，`qa_dir=temp/calibration_qa`。

## 5. 功能 1：制板流程

对等 C++ 门面 `cam::MakeBoard` → `GenerateCheckerboardBoard`。入参只有 ini 路径；版面参数全部来自 `[checkerboard]`，缺键用第 4.3 节缺省。三个产物都成功写出才返回 true。

### 5.1 调用顺序（必须按此，失败即停并返回对应 `err_msg`）

1. 加载 ini（失败则返回配置类错误；制板路径不额外包一层「读取标定配置失败」）。
2. **先校验版面**（第 5.2 节，含方向标记不相交）。校验失败不得创建产物文件。
3. 创建 `out_dir`（不存在则递归创建）。失败：`创建输出目录失败：{out_dir}（{系统原因}）`。
4. 写 `checkerboard.pdf`。打不开：`无法创建文件：{path}`；写出失败：`写入文件失败：{path}`。
5. 写 `checkerboard_preview.png`。失败：`保存预览图失败：{path}`。
6. 写 `打印说明.txt`（utf-8-sig）。失败文案同 PDF 的创建/写入句。
7. 打成功日志：三个实际路径；预览图注明「仅供核对，勿用于打印」；并输出与 C++ 同类的版面摘要（纸张、格数、格边长、内角点数、角点覆盖跨度 `(cols-2)*square_mm` × `(rows-2)*square_mm`）。

文件名固定为上述三个；打印说明**不得**写成 C++ 现网的 `Readme.txt`。

### 5.2 校验顺序与几何公式

坐标系：原点在纸张**左下角**，单位毫米，x 向右、y 向上（PDF 用户空间约定）。

1. **参数合法性**：`square_mm > 0`、`paper_w_mm > 0`、`paper_h_mm > 0`、`cols >= 2`、`rows >= 2`、`border_mm >= 0`。任一不满足：`参数非法：格子边长/纸张尺寸必须为正，横纵格数必须不小于 2`（负的 `border_mm` 也归入此句，对等 C++ `LayoutBoard`）。
2. 图案尺寸与居中留白：
   - `pattern_w = square_mm * cols`
   - `pattern_h = square_mm * rows`
   - `ox = (paper_w_mm - pattern_w) / 2`
   - `oy = (paper_h_mm - pattern_h) / 2`
3. 若 `ox < border_mm`：`横向留白不足：需要至少 {border}mm，实际仅 {ox}mm`（1 位小数）。
4. 若 `oy < border_mm`：`纵向留白不足：需要至少 {border}mm，实际仅 {oy}mm`。
5. 横纵格数必须一奇一偶（避免 180° 旋转歧义）：若 `(cols % 2) == (rows % 2)`，失败：`横纵格数必须一奇一偶（当前 {cols}x{rows} 存在 180° 旋转歧义）`。出厂 35×28 满足此约束。
6. **方向标记不得与棋盘相交或压线**（C++ 现网无此校验，本工程必须做）。计算标记后做轴对齐矩形相交判定，见第 5.4 节。

### 5.3 黑格规则与方向标记定位

- 行 `r`、列 `c` 从图案左下角起算（`r,c` 从 0 计）。当 `(r + c) % 2 == 0` 时为黑格。黑格矩形：`(ox + c * square_mm, oy + r * square_mm, square_mm, square_mm)`。
- 方向标记：左上角白边内一根黑色细长条，用于辨识摆放方向。
  - `mark_w = 0.6 * square_mm`
  - `mark_h = 0.15 * square_mm`
  - `mark_x = ox * 0.4`
  - `mark_y = paper_h_mm - oy * 0.4 - mark_h`
- 默认定位公式在留白足够时与 C++ 完全相同，**不另改位置公式**。只是在相交时改为失败，而不是画出侵入棋盘的标记。

出厂配置（15 mm 格，555×450 mm 纸，35×28）下：`ox = oy = 15`，`pattern_w = 525`，`pattern_h = 420`，标记位于上边距内，与图案不相交。

### 5.4 轴对齐矩形相交 / 压线校验

图案矩形：`P = [ox, oy, pattern_w, pattern_h]`（左下角 + 宽高）。
标记矩形：`M = [mark_x, mark_y, mark_w, mark_h]`。

两矩形在任一轴上**严格分离**才视为不相交；边重合（压线）视为相交：

```text
separated = (M.x + M.w < P.x) or (P.x + P.w < M.x) or (M.y + M.h < P.y) or (P.y + P.h < M.y)
intersect = not separated
```

仅要求 `ox/oy ≥ border_mm` **不足以**防止合法配置下标记侵入。反例（必须失败、不得产出任何三件套，含打印说明）：

- `cols=35, rows=28, square_mm=15, paper_w_mm=540, paper_h_mm=423, border_mm=0`
- 此时 `ox=7.5`、`oy=1.5`，留白校验通过，但标记进入图案。
- 文案：`方向标记侵入棋盘图案（标记 [{x},{y},{w},{h}]mm，图案 [{ox},{oy},{pw},{ph}]mm），请加大纸张或留白，或减小格数/格边长`

### 5.5 PDF：库选择与页面尺寸

**选用 reportlab 生成矢量 PDF**，理由：

1. 可把页面尺寸精确设为 `paper_w_mm × paper_h_mm`，换算 `1 mm = 72/25.4 pt`（reportlab 的 `mm` 单位即此定义），满足 100% 实际大小打印，不依赖栅格放大。
2. 只画填充矩形，API 稳定，免于手写 PDF 1.4 与 xref 偏移（C++ 为零依赖才手写；Python 无此必要）。
3. 不要求与 C++ PDF 字节级一致，只要求几何等价、边缘锐利。

实现要点：

- 页面 `pagesize = (paper_w_mm * mm, paper_h_mm * mm)`。验收允许换算误差在 0.1 mm 以内。
- 填充色纯黑；每个黑格与方向标记用用户空间毫米坐标画填充矩形（无描边）。
- 交打印店只打这一个文件。不要把预览 PNG 嵌入 PDF，不要把预览图当作打印稿。

### 5.6 预览图

- 文件名：`checkerboard_preview.png`。
- 尺度与 C++ 相同：`4.0` 像素/毫米。图像宽高：`round(paper_w_mm * 4.0)`、`round(paper_h_mm * 4.0)`。舍入必须用 Python 3 的 `round`（四舍六入五成双，对等 C++ `llrint` / `FE_TONEAREST`），以保证任意参数组合下与 C++ 预览几何一致。
- 画布为 8 位 BGR 白底 `(255,255,255)`。毫米（左下原点）转像素（左上原点）：
  - `x0 = round(rc.x * 4.0)`
  - `y0 = round((paper_h_mm - rc.y - rc.h) * 4.0)`
  - `x1 = round((rc.x + rc.w) * 4.0)`
  - `y1 = round((paper_h_mm - rc.y) * 4.0)`
  - 用 OpenCV `cv2.rectangle(..., color=(0,0,0), thickness=cv2.FILLED)` 填充（含标记）。
- 最外框灰色折线 `(180,180,180)`，线宽 1，对角 `(0,0)` 与 `(w-1, h-1)`。
- **不得用于打印**；日志必须写明。

### 5.7 打印说明

- 文件名：**`打印说明.txt`**（有意不跟 C++ 现网的 `Readme.txt`）。
- 编码：**utf-8-sig**（先写 BOM `EF BB BF`，再写 UTF-8 正文），便于 Windows 记事本打开。
- 正文按需求附录 A 展开，不得再照抄 C++ `BuildPrintNote` 的两处错误（把 `border_mm` 写成四边边距；格数不足 10 时仍写“连续 10 个格子”）。

展开规则：

- `{ox}` / `{oy}` 为居中后的**实际留白**，不是 `border_mm`。
- `{nx} = min(10, cols)`，`{ny} = min(10, rows)`。
- `{span_x} = nx * square_mm`，`{span_y} = ny * square_mm`。
- `{pattern_w}` / `{pattern_h}` / `{paper_w}` / `{paper_h}` / `{square}` / `{cols}` / `{rows}` 取当前配置。
- 第 3 款：当 `nx == ny`，直接比较两条实测跨距，差不超过 0.3 mm；当格数不同，先各自除以所用格数得到单格边长再比，差不超过 0.03 mm。
- 数值格式对等 C++ 打印说明里的 `%g`（默认 6 位有效数字、去无意义尾零），使出厂配置写出 `555`、`450`、`15`、`525`、`420`、`150` 而不是 `15.000000`。
- 必须包含「方向标记……请勿当作脏点修掉」及 100% 实际尺寸、关闭「适应页面 / 适合纸张 / 自动缩放」等条款（原意保持）。

出厂配置下：`{ox}` 与 `{oy}` 均为 15，`{nx}` 与 `{ny}` 均为 10，`{span_x}` 与 `{span_y}` 均为 150，`{pattern_w}` 为 525，`{pattern_h}` 为 420。

正文模板（实现时按占位符展开，结构不得删减）：

```text
棋盘格标定板打印说明
============================================================

一、交付文件
- checkerboard.pdf：矢量打印文件（只需打印这一个文件）

二、成品规格
- 纸张成品尺寸：{paper_w} × {paper_h} mm（宽 × 高），幅面需 A1 及以上，印后裁切
- 棋盘格图案：{cols} 列 × {rows} 行，格子边长 {square} mm（黑白相间）
- 图案区域：{pattern_w} × {pattern_h} mm，左右各留 {ox} mm、上下各留 {oy} mm 白色边距
- 方向标记：左上角白边内有一根黑色细长条，用于辨识摆放方向，属正常设计，
  请勿当作脏点修掉

三、打印要求（重要，请逐条落实）
1. 请用 PDF 原文件直接输出，不要转成 JPG/PNG 图片后再打印；
2. 必须 100% 实际尺寸打印，关闭"适应页面 / 适合纸张 / 自动缩放"等一切缩放选项；
3. 打印分辨率不低于 600 DPI，建议 1200 DPI；
4. 纸张用哑光厚卡纸或铜版纸（克重 ≥200g），黑白打印、纯黑实底；

5. 印后按 {paper_w} × {paper_h} mm 裁切成品（裁切偏差 ±1mm 内可接受，
   图案本身的尺寸精度才是关键）。

四、印后验收指标（请配合实测后告诉我们数值）
1. 横向连续 {nx} 个格子的总宽度：应为 {span_x} mm，偏差不超过 ±0.5 mm；
2. 纵向连续 {ny} 个格子的总高度：应为 {span_y} mm，偏差不超过 ±0.5 mm；
3. 横向与纵向须比例一致：所用格数相同时，两条实测跨距之差不超过 0.3 mm；
   所用格数不同时，先各自除以格数得到单格边长再比较，差不超过 0.03 mm；
4. 格子边缘平直无锯齿，黑白分明无灰边。
如任何一项不达标，请先不要裁切交付，联系我们调整后再印。
```

另用一组格数不足 10 但留白与标记均合法的配置做验收时，条款须按实际格数写出，且不得再出现「连续 10 个格子」。将纸张加大使实际留白大于 `border_mm` 时，说明写的是实际 `ox`/`oy`，不是 `border_mm`。

## 6. 功能 2：标定流程

对等 C++ 门面 `cam::Calibrate`（单张走 `BuildCalibrationFile`，多张走 `BuildCalibrationFileFromImages`，收尾共用 `FinishCalibrationAndQa`）。本工程对外只保留一个 `calibrate()`，内部按列表长度分支，但控制流与产物必须与基线一致。

### 6.1 总体控制流

配置成功读出后即填写 `report.xml_path`（绝对路径）。之后：

1. 空列表 → 失败：`无标定采图（图像列表为空），无法标定`。
2. 逐张：转 8 位灰度；格式不支持则失败（单张用「棋盘格图像格式不支持（须为 8UC1/8UC3/8UC4）」；多张用「第 {i} 张标定采图格式不支持（须为 8UC1/8UC3/8UC4）」，`i` 从 1 起）。尺寸必须与首张一致，否则：`第 {i} 张标定采图尺寸 ({w}, {h}) 与首张 ({w0}, {h0}) 不一致`。
3. 对每张做角点检测；任一张失败则**整体失败**：`第 {i} 张标定采图角点检测失败: {具体原因}`（单张可直接使用检测函数自己的文案，不必再套「第 1 张」前缀，与 C++ 单图入口一致）。
4. 多张时对各图角点取算术均值后再求解，并打 Info：`多图标定采图 {n} 张全部检测成功，角点取均值降噪` 以及求解侧的 `角点集合 {n} 张取均值，每张 {k} 点`。
5. 求解并写出 XML（无论质量是否达标，只要求解成功，**仍写入正式 `out_xml`**，与 C++ 一致）。质量不达标时 **禁止现场在 `ok=false` 后启用该文件**（见第 10.1 节），但本工程仍覆盖正式路径，不改为写入诊断目录。
6. **RMS 超限后的控制流必须与 `FinishCalibrationAndQa` 一致**：求解函数在 `RMS > 0.3 px` 时可以先给出中间态错误句并返回 false，但只要 XML 已写出，后续仍须继续：回读 XML、在 debug 打开时生成 QA、做正射验证，再以**总质量门禁句**覆盖对外 `err_msg`。不得在 RMS 超限后提前结束而跳过验证。
7. 若求解硬失败（XML 未写出），回读失败时对外透传求解阶段错误，不再做 QA 与验证。
8. 回读成功后把 `report.rms` 写成文件中的 RMS。验证完成后（成功时）填写 `verify_mean_px` / `verify_p95_px`；验证未完成则保持 0，总门禁句 mean 处写「未通过」。

### 6.2 图像格式与读盘

- 门面输入支持 8 位灰度、24 位、32 位图（对等 `8UC1` / `8UC3` / `8UC4`），内部自动转灰度：`8UC1` 原样；`8UC3` 按 `COLOR_BGR2GRAY`；`8UC4` 按 `COLOR_BGRA2GRAY`。其它类型视为格式不支持（空灰度）。
- 命令行读盘：先 `cv2.imread(path, cv2.IMREAD_UNCHANGED)`。若验收用图或现场 24/32 位 BMP 出现 OpenCV 读失败，实现阶段须补与 C++ `DecodeBmpManual` 对等的手工 BMP 兜底（`BI_RGB` / `BI_BITFIELDS`、底向上/顶向下），不得把“读失败”误判成“格式不支持”。读盘失败文案是 `图像读取失败: {path}`。

### 6.3 角点检测（SB + 亚像素）

对等 C++ `DetectBoardCorners`，参数必须钉死为基线取值，不得改窗口或另加标志：

1. `pattern_cols <= 0` 或 `pattern_rows <= 0`：`内角点配置非法: {cols}x{rows}`。
2. `cv2.findChessboardCornersSB(gray, (pattern_cols, pattern_rows), flags=cv2.CALIB_CB_NORMALIZE_IMAGE)`。只使用这一标志（含图像归一），**不得**再加 `EXHAUSTIVE`、`ACCURACY`、`EXPLICIT` 等。
3. 检出成功且数量必须恰好等于 `pattern_cols * pattern_rows`，否则：`未检测到完整棋盘格（目标 {cols}x{rows}={n} 个内角点），请检查标定板摆放与成像`。检测抛异常：`棋盘格检测异常: {原因}`。
4. 亚像素细化：`cv2.cornerSubPix(gray, corners, winSize=(21, 21), zeroZone=(-1, -1), criteria=(cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.01))`。异常：`角点亚像素细化异常: {原因}`。
5. 角点顺序为行优先，须与物点网格顺序一致。成功时 Info：`棋盘格角点检测成功: {n} 个`。

多图均值：各张点数须一致，否则 `各图角点数量不一致`。点数还须等于内角点配置，否则 `角点数量 {n} 与内角点配置 {cols}x{rows}={expect} 不符`。均值是对应下标的算术平均（`float32` 像素坐标，对等 `MeanCorners`）。图像尺寸非法（宽或高 ≤ 0）：`标定图尺寸非法`。无角点集合：`无角点集合，无法标定`。

### 6.4 物点网格与求解约束

物点网格（单位毫米，板面 z=0，行优先，对等 `BuildObjectGrid`）：

```text
for r in 0 .. pattern_rows-1:
    for c in 0 .. pattern_cols-1:
        (c * square_x_mm, r * square_y_mm, 0)
```

单视图求解：把**均值角点**作为一组观测，调用 `cv2.calibrateCamera`。

- 标志**只**使用 `cv2.CALIB_FIX_ASPECT_RATIO | cv2.CALIB_FIX_PRINCIPAL_POINT`（fx=fy，主点固定在图像中心）。**不得**再启用 rational / thin-prism / tilted 或其它畸变模型，不得加 `CALIB_RATIONAL_MODEL`、`CALIB_THIN_PRISM_MODEL`、`CALIB_TILTED_MODEL`、`CALIB_FIX_K3` 等。
- 传入空的 `cameraMatrix` 与 `distCoeffs`（不预填、不加 `CALIB_USE_INTRINSIC_GUESS`），让 OpenCV 按与 C++ 相同的方式初始化；`FIX_ASPECT_RATIO` 在空矩阵时按 1:1 处理，从而 fx=fy。
- 畸变固定为 5 项 `k1,k2,p1,p2,k3`。写出前把 `dist_coeffs` 整形为 **1×5**、`float64`。不得写出 8/12/14 项。
- `camera_matrix` 必须是 **3×3**、`float64`（不得写成 9×1 或 1×9）。主点应为图像中心；实现上以求解结果为准并在对拍中核验。
- `rvec` / `tvec` 取第 0 组外参，整形为 **3×1** `float64`；`tvec` 单位为毫米。
- 求解异常：`标定求解失败: {原因}`。外参缺失或 RMS 非有限值：`标定求解结果非法（外参缺失或 RMS 非有限值）`。

### 6.5 RMS 分级日志（仅日志，不单独改变对外返回值）

阈值与 C++ 相同：`kRmsGood = 0.1`，`kRmsWarn = 0.3`（单位 px）。RMS 格式 4 位小数。

- `RMS ≤ 0.1`：Info `标定 RMS 重投影误差 {rms} px（达标 ≤0.1）`
- `0.1 < RMS ≤ 0.3`：Warn `标定 RMS 重投影误差 {rms} px（偏高，建议检查印刷与采图）`
- `RMS > 0.3`：Warn `标定 RMS 重投影误差 {rms} px（超 0.3 告警线，残差矢量图排查印刷缺陷）`

随后 Info 打印焦距（1 位小数）与 5 项畸变系数（4 位小数）。XML 成功写出后 Info：`标定参数已保存: {xml}`。若 `RMS > 0.3`，求解阶段可记中间态错误句并返回 false，但收尾流程必须继续。

### 6.6 XML 字段、形状与回读

用 OpenCV `FileStorage`（XML）写出，字段名、矩阵形状与数值语义必须可被现有 C++ `LoadCalibrationXml` 回读。写出字段与顺序对等 `SaveCalibrationXml`：

| 字段 | 类型与形状 | 含义 |
|---|---|---|
| `camera_matrix` | 3×3，64 位浮点 | fx=fy，主点为图像中心。C++ 按 `rows==3 && cols==3` 校验，写成 9×1/1×9 会回读失败 |
| `dist_coeffs` | 1×5，64 位浮点 | `k1,k2,p1,p2,k3`；回读按元素总数为 5 校验 |
| `rvec` | 3×1，64 位浮点 | 板面外参旋转向量 |
| `tvec` | 3×1，64 位浮点 | 板面外参平移，单位 mm |
| `image_width` / `image_height` | 整数 | 标定图像素尺寸 |
| `square_x_mm` / `square_y_mm` | 浮点 | 所用格距（毫米），来自配置（跟随或回填） |
| `pattern_cols` / `pattern_rows` | 整数 | 内角点行列数 |
| `rms` | 浮点 | RMS 重投影误差（px） |
| `mm_per_px` | 浮点 | 正射刻度，来自 `target_mm_per_px` |
| `created` | 字符串 | 写出时的**本地时间**，格式必须为 `YYYY-MM-DDTHH:MM:SS`（对等 C++ `NowTimeString`：`strftime("%Y-%m-%dT%H:%M:%S")` + 本地时区）。不含时区后缀、毫秒，也不得写成 UTC/`Z`。Python 使用 `datetime.now().strftime("%Y-%m-%dT%H:%M:%S")`（本地时钟，不用 `timezone.utc`） |

父目录不存在则创建；失败：`创建标定输出目录失败: {dir}，{系统原因}`。`FileStorage` 打不开：`标定文件无法写入: {path}`；写出异常：`标定文件写入异常: {path}，{原因}`。

回读完整性校验（对等 C++，用于写出后自检；亦应作为本工程内部加载实现）：

- `camera_matrix` 必须是 3×3 且非空；`dist_coeffs` 元素总数为 5；`rvec`/`tvec` 元素总数为 3；宽高和内角点均为正。
- 然后把矩阵归一到 64 位浮点：`camera_matrix` 保持 3×3，`dist_coeffs` reshape 为 1×5，`rvec`/`tvec` reshape 为 3×1。
- 回读失败对外：`标定文件回读失败: {原因}`（若求解硬失败未写出 XML，则透传求解错误，见 6.1）。

### 6.7 正射变换约定（功能 2 内部，不是功能 3）

对等 C++ `Rectifier::Load` / `Rectify`。必须分清**输出像素尺寸**和**物理覆盖范围**：

- **输出像素尺寸**与标定输入图像相同（宽 `w`、高 `h`），**不**随 `target_mm_per_px`（记为 `s`）改变。不得再沿用「适应页面 / 刻度影响输出图大小」的错误说法。
- `s` 改变的是：每个输出像素对应的板面毫米数，以及输出画面所覆盖的板面范围。增大 `s` 会看向更广的板面，减小 `s` 则相反；输出宽高像素数不变。
- **中心锚点**：以输入图像中心像素 `cx = (w-1)/2`、`cy = (h-1)/2` 反投影到板面 `z=0`，得到 `(Xc, Yc)`，作为输出图中心对应的板面毫米坐标。
  - 反投影算法对等 `PlaneIntersectBoard`：`cv2.undistortPoints` 得归一化坐标 → 射线 `(x,y,1)` → `R = Rodrigues(rvec)`，`a = Rᵀ · ray`，`b = -(Rᵀ · t)`，若 `|a_z| < 1e-12` 则失败（视线与板面近乎平行），否则 `λ = -b_z / a_z`，`(X,Y) = (λ·a + b)` 的前两分量。
- **方向判定**（防镜像）：将板面点 `(Xc,Yc,0)`、`(Xc+1,Yc,0)`、`(Xc,Yc+1,0)` 用 `cv2.projectPoints`（同一 K、5 项畸变、外参）正投影回原图，得到 `p0,p1,p2`。`sign_x = +1 if (p1.x-p0.x) ≥ 0 else -1`，`sign_y = +1 if (p2.y-p0.y) ≥ 0 else -1`。若板面 X 轴在图像中更接近竖直（`|(p1.y-p0.y)| > |(p1.x-p0.x)|`），记警告「板面 X 轴在图像中更接近竖直方向……」，**不失败**。
- 输出像素 `(u,v)` 对应板面：`X = Xc + sign_x * (u-cx) * s`，`Y = Yc + sign_y * (v-cy) * s`，再经相机内参、5 项畸变与外参正投影回原图取色。映射表以 `float32` 的 `map_x`/`map_y` 存储，可用与 C++ 相同的 256 行分块以控制内存。
- **插值**：线性插值（`cv2.INTER_LINEAR`）。**边界填充**：常数 0（`cv2.BORDER_CONSTANT`，黑色）。
- **物理覆盖范围**：约 `(w-1)*s` 毫米 × `(h-1)*s` 毫米，中心在 `(Xc, Yc)`。
- 逆变换（验证网格用，对等 `BoardMmToPx`）：`u = cx + sign_x * (X - Xc) / s`，`v = cy + sign_y * (Y - Yc) / s`。
- `s <= 0` 时构建失败（中文原因说明必须为正）。Load 或 Rectify 失败分别对应 `构建正射矫正映射失败: {原因}`、`正射矫正输出为空`。Rectify 输入尺寸必须与标定 `image_size` 一致；非单通道则转灰度并警告。

多图时 QA 与验证均以**输入列表的第一张**为代表图（命令行则是按第 3.5 节排序后的第一张）。

### 6.8 验证闭环统计

对正射图再次调用第 6.3 节角点检测（同一内角点配置）。重检失败：记 Error `正射校正图角点重检失败，验证闭环中断: {原因}`，`validateOk=false`，**不生成**第 4 张 QA，进入总门禁（mean 处写「未通过」）。

重检成功后：

- 将物点网格经 `BoardMmToPx` 得到理想像素点，与重检角点逐点求欧氏距离。
- `mean_px` 为平均值；`p95_px` 对等 NumPy `percentile(..., 95)` 的线性插值：将误差升序排列，`pos = 0.95 * (n-1)`，在 `floor(pos)` 与 `ceil(pos)` 之间线性插值。`max_px` 为最大误差。`mean_mm = mean_px * s`，`max_mm = max_px * s`。
- 行/列直线度（每行/列 `fitLine` DIST_L2 后的最大垂直偏差）写入日志，**不作为质量门禁**。
- Info 日志格式对等 C++：`校正验证: 残差 mean {..}px / p95 {..}px / max {..}px（{max_mm}mm），行直线度 {..}px，列直线度 {..}px`。

### 6.9 QA 规则

仅当 `save_intermediate=true`。验证通过时为 4 张；正射重检失败时只落前 3 张（若当时已生成），第 4 张可不生成。不要把本开关理解成“打开就必然有 4 张”。`false` 或缺键时不落过程图，但 XML 仍按第 6.1 节写出。

验收必须使用**全新空的** `qa_dir`（或先清空），避免旧的 `04_verify_grid.bmp` 被误判为本次产物。

文件名与画法必须与 C++ 一致：

| 文件名 | 含义与画法 | 何时写出 |
|---|---|---|
| `01_corners_overlay.bmp` | 代表图转 BGR，`drawChessboardCorners` 叠加**均值角点**；ASCII 标注 `corners {c}x{r}={n}` | debug 打开且已进入 QA 流程 |
| `02_residual_vectors.bmp` | 残差矢量：检测点（均值角点）指向模型投影点（`projectPoints` 用 XML 回读的 K/畸变/外参与物点网格），矢量放大 **50** 倍；红箭头、检测处绿实心圆半径 3。标注含 `residual x50` 以及这组重投影误差的 mean/p95/max（3 位小数） | 同上。`projectPoints` 失败则接口失败：`重投影计算失败: {原因}`（这不是“写盘失败”） |
| `03_rectified.bmp` | 正射校正图（灰度） | 正射图生成成功后 |
| `04_verify_grid.bmp` | 理想网格空心绿圈半径 5、线宽 1；实测角点实心红点半径 3。标注 `rectified residual  mean {..}px  max {..}px ({..}mm)` | **仅当**正射图上角点重检成功并完成验证统计后 |

QA 标注文字用 `cv2.putText`，位置/样式对等 C++ `PutQaText`：原点 `(40, 60)`，`FONT_HERSHEY_SIMPLEX`，字号 1.3，颜色 BGR `(0, 220, 220)`，线宽 2，`LINE_AA`（不支持中文，保持 ASCII）。残差箭头对等 `cv2.arrowedLine(..., color=(0,0,255), thickness=2, lineType=LINE_AA, shift=0, tipLength=8.0)`（与基线入参一致，用于视觉对等；QA 图不纳入数值对拍门禁）。

闭合规则：

- 创建 `qa_dir` 失败：接口失败，`创建 QA 目录失败: {qa_dir}，{系统原因}`。
- **单张 QA 写盘失败**：只记日志，**不因此让标定接口失败**；已写出的 XML 与已成功落盘的 QA 图保留，失败的那张可以缺失。对等 C++：`SaveImage` 返回值在 QA 路径上未被当作接口失败条件。
- debug 打开且正射重检失败：只落前 3 张（若已生成），可以不生成第 4 张；接口仍走到总门禁。

### 6.10 质量门禁与对外 `err_msg`

同时满足以下两项才返回 true（标定成功且质量达标）：

| 指标 | 门禁 |
|---|---|
| RMS 重投影误差 | **≤ 0.3 px** |
| 正射验证闭环平均残差 mean | **≤ 0.5 px**（超过或验证未通过则失败；验证未完成时 report 该值为 0，不得当作达标） |

门禁数值与 C++ 现网一致，本阶段不调整，也不改为物理量门禁。对拍冻结 `target_mm_per_px=0.136`。注意 `verify_mean_mm = verify_mean_px × target_mm_per_px`，像素门禁的物理含义随该刻度变化，故不得改刻度缺省。

收尾判定（对等 `FinishCalibrationAndQa` 末尾）：若求解未达 RMS 门禁（`solveOk==false`），或 `validateOk==false`，或 `mean_px > 0.5`，则对外 `err_msg` 使用第 3.6 节**总门禁句**并返回 false。XML（及 debug 打开时按 6.9 规则产生的 QA）仍保留。

收尾成功日志：`标定完成: RMS {rms}px, 焦距 {fx}px, 参数文件 {xml}`；debug 打开时再 Info `质检图见 {qa_dir}`。

### 6.11 采图使用约束（写入 README / 操作说明，不是代码强制上限）

- 建议 3～5 张连拍；单张可以求解；超过 5 张收益递减，不必作为强制上限。
- 连拍期间相机、镜头和标定板都须保持静止；机位、镜头、分辨率还必须与后续正式使用完全一致。
- 标定板须吸风展平，与生产同光源、同工作距离；尽量充满画面，四周静区完整可见。
- 角点检出数必须恰好等于内角点数（出厂跟随制板：35×28 格 → **34×27** 内角点）。
- 打印后应用卡尺实测格距；与 `[checkerboard] square_mm` 有偏差时，回填 `[calibrate] square_x_mm` / `square_y_mm`。

## 7. 依赖与虚拟环境

### 7.1 运行环境

- 目标操作系统：Windows 10 / Windows 11（64 位）。
- 使用**独立虚拟环境**（`python -m venv .venv`），不污染系统 Python。依赖只安装在该 venv 中。
- 解释器建议：**CPython 3.11 64-bit**（亦允许 3.10）。依据：PyPI 上 `opencv-python 4.8.0.76` 的官方分类器覆盖 3.6–3.11，Windows 轮子为 `cp37-abi3-win_amd64`。不要默认使用 3.12+（不在该发行版分类器内，需额外验证才能放开）。

### 7.2 OpenCV 必须钉死 4.x

C++ 基线为 **OpenCV 4.8.0**。Python 工程的 OpenCV **大版本必须钉死为 4.x**，禁止升到 5.x，禁止在实现过程中随意更换次版本。验收对拍与基准结果冻结都使用本文钉死的发行版。

查得 PyPI 现有 4.8.x 发行版包括：`4.8.0.74`（首个 4.8.0 轮子）、`4.8.0.76`（同一 OpenCV 4.8.0，含 typing 修复）、`4.8.1.78`（OpenCV 4.8.1，并修复轮子内 libwebp 的 CVE-2023-4863）。

**本设计钉死：`opencv-python==4.8.0.76`。** 理由：与 C++ 基线同为 OpenCV 4.8.0，对拍时算法差异最小。不要使用 `opencv-contrib-python`（避免同一 `cv2` 命名空间冲突，本范围也不需要 contrib 模块）。

说明：`4.8.0.76` 轮子捆绑的 libwebp 受 CVE-2023-4863 影响。本工具现场主路径是本地 BMP/PNG 采图与 reportlab 矢量 PDF，不把未受信的互联网 WebP 作为输入，残余风险有限。若安全策略强制要求补丁，只允许在 4.8.x 内改钉到 `4.8.1.78`，并且必须重新跑 C++ 基线对拍并更新冻结基准；**禁止**为此升到 4.9+ 或 5.x。

实现时在启动或自检中记录 `cv2.__version__`（应为 `4.8.0`），避免安装错包。

### 8.3 C++ 基准与允许误差建议

在提交 `ea3320df35acb1ba77c20b452ead6c7c0a355f4f`、C++ OpenCV 4.8.0 上，对冻结清单跑功能 2（建议同时跑：单张=第一张；多张=前 3 张），记录并冻结：

- RMS，验证 mean / p95
- `fx`（及完整 `camera_matrix` 3×3）
- `dist_coeffs` 五项
- （建议一并记录，不作为对外门面字段）`rvec`/`tvec`、`image_width`/`image_height`

Python 侧使用钉死的 `opencv-python==4.8.0.76` 对同一清单、同一 ini（跟随出厂格距、`target_mm_per_px=0.136`）求解。允许误差建议如下——须小到能发现“标志加错、网格行列搞反、未做亚像素、矩阵形状不对、刻度用错”等算法偏离，又容忍浮点与绑定层的细微差异。同一 OpenCV 4.8.0 下预期应非常接近；若超差，先查版本、图顺序、跟随键和标志位，不要轻易放宽。

| 量 | 建议允许绝对偏差 | 说明 |
|---|---|---|
| RMS | ≤ 1×10⁻⁴ px | 与门禁 0.3 px 相比极严，用于发现求解不一致 |
| `verify_mean_px` / `verify_p95_px` | ≤ 1×10⁻³ px | 含重检与 remap 的累积误差 |
| `fx`（且须 `fx == fy`） | ≤ 0.05 px | 焦距对初值与迭代敏感，但仍应同量级吻合 |
| 主点 `cx, cy` | 须等于 `(w-1)/2`、`(h-1)/2`（建议 ≤ 1×10⁻⁶ px 的数值噪声） | `CALIB_FIX_PRINCIPAL_POINT` 的硬约束 |
| `camera_matrix` 非对角元 | ≤ 1×10⁻⁹（相对 0 或相对 C++） | 应为 0 |
| `dist_coeffs` 五项（逐项） | ≤ 1×10⁻⁶ | 5 项模型，不得出现第 6 项及以后 |
| 正射输出图宽高 | 与输入图完全相同 | 不随 `s` 改变 |
| XML `created` | 符合本地时间格式，不与 C++ 比绝对时刻 | 只验格式与“是本地时而非 Z” |

上述阈值在实现阶段跑出 C++ 基准并完成第一次对拍后可以微调，但须记录理由，且不得宽到掩盖算法错误（例如把 RMS 容差放到 0.05 px 是不可接受的）。

另核验：XML 可被 OpenCV `FileStorage` 及现有 C++ `LoadCalibrationXml` 回读；`camera_matrix` 为 3×3；`dist_coeffs` 恰好 5 项；`created` 为 `YYYY-MM-DDTHH:MM:SS`。

### 8.4 两类质量失败用例（须先在 C++ 基线上跑通再冻结）

构造目标（不在本文指定唯一手法，实施时必须跑通再写入测试清单）：

1. **仍能检出角点并求出 XML，但 RMS > 0.3 px**。候选：对合法采图做可复现的几何扰动或额外畸变（例如固定种子的位移场/径向畸变预畸变）以抬高 RMS。
2. **仍能求解，但正射验证 mean > 0.5 px，或重检失败（验证未通过）**。候选：用可复现方式改变采样范围或图像条件（例如临时把 `target_mm_per_px` 改到会裁掉角点静区的值，或对代表图做可复现模糊后再走验证——注意若改刻度，该用例须与“对拍冻结 0.136”的主路径测试分开，避免污染主基准）。

验收要点：

- 返回失败，正式 `out_xml` 仍写出（及 debug 打开时按第 6.9 节规则产生 QA）。
- `report` 含已算出的数值；验证未完成时 verify 字段为 0。
- 对外 `err_msg` **只对照总门禁句**，不得对照“超过 0.3 px 门禁（标定文件仍已写出…）”那句中间态。
- RMS 超限用例必须确认已经做过正射验证（报告里有验证结果，或 mean 处为「未通过」），而不是停在求解阶段。
- 使用空的 `qa_dir`。

其它功能 2 用例（需求 10.2）：空列表；模糊/缺角导致检测失败；3 张中一张改分辨率导致“第 N 张”尺寸不一致；跟随与名义格距告警（把 `square_mm` 改成非 15 的合法值，告警数字跟着变；显式回填后即使是 15.0 也不再告警）；`save_intermediate` 真/假/缺键；命令行扩展名过滤、不递归、排序、坏图整次失败。

### 8.5 制板边界用例

1. 出厂配置：三件套生成成功；PDF 页面 555 mm × 450 mm（允许 0.1 mm 换算误差）；图案居中；黑白格与方向标记符合第 5 节；预览 4.0 px/mm；打印说明为 utf-8-sig、文件名为 `打印说明.txt`，`ox`/`oy` 为 15，跨距 10 格 / 150 mm。
2. 横纵同奇或同偶（如 35×35）：失败，一奇一偶句式。
3. 纸张改小导致留白不足：横向/纵向留白不足句式，含需要值与实际值。
4. 格数 < 2 或边长非正：参数非法句式。
5. 第 5.4 节反例（35×28、15 mm 格、540×423 mm、`border_mm=0`）：必须失败，方向标记侵入句式，**不得产出打印说明或其它产物**。
6. 格数不足 10 但留白与标记均合法：打印说明跨距按实际格数，不得出现「连续 10 个格子」。
7. 纸张加大使实际留白大于 `border_mm`：打印说明写实际 `ox`/`oy`，不是 `border_mm`。
