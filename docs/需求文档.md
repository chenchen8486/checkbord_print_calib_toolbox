## 1. 目标

把 C++ 工程 `Calibrate_and_Measure` 的**功能 1（生成标定板打印文件）**和**功能 2（相机标定）**做成一套**能力相同**的 Python 工程，供现场制板、采图标定，并产出可被现有 C++ 测量链路继续使用的标定文件。

本工程要达到的结果：

1. 按同一份 ini 配置，生成与 C++ 功能 1 等价的打印三件套，交打印店按 100% 实际大小印刷。
2. 对 1～n 张棋盘格采图求解标定，写出与 C++ 功能 2 字段一致、可被 OpenCV `FileStorage`（含现有 C++ `LoadCalibrationXml`）读取的 XML，并在调试开关打开时输出同等含义的 QA 质检图。
3. 质量判定、失败时的产物保留策略、中文错误信息与 C++ 门面行为对齐，调用方按返回值处理，接口不向外抛异常。

成功标准以第 10 节验收条款为准，而不是“代码从 C++ 逐行翻译”。

## 3. 通用约定

以下约定对齐 C++ README 第 3 节与 `cam_api.h` 的设计说明，本工程功能 1、功能 2 都适用。

1. **配置入口**：所有参数集中在一份 utf-8 ini（可带 BOM，解析时跳过）。每个对外接口都以 ini 路径为配置入口，显式传入，无隐式全局配置。建议调用方传绝对路径。
2. **相对路径**：ini 内的相对路径一律相对**该 ini 文件所在目录**解析，ini 可放在任意位置。
3. **错误模型**：制板与标定返回成功/失败（布尔）+ 输出参数 `err_msg`（中文原因）。接口内部捕获异常，**不向调用方抛异常**。失败时 `err_msg` 必须为可读中文，用词与第 9 节对齐。
4. **日志**：运行过程输出中文分级日志（Debug / Info / Warn / Error）。集成方可改接到自己的日志系统，但不因此改变对外返回值。
5. **图像格式**：功能 2 输入支持 8 位灰度、24 位、32 位图（对等 C++ 的 8UC1/8UC3/8UC4），内部自动转灰度。不支持的格式必须失败并给出第 9 节对应文案。
6. **编码**：源码、ini、打印说明文本使用 UTF-8；打印说明写出时使用 utf-8-sig（带 BOM），便于 Windows 记事本打开。打印说明的**文件名**固定为 `打印说明.txt`，这是相对 C++ 现网 `Readme.txt` 的有意差异（见第 11 节 D）。
7. **运行环境**：Windows 10/11；独立虚拟环境，不污染系统 Python。解释器版本与依赖在设计阶段确定；其中 OpenCV 大版本必须在设计阶段钉死（见第 1.1 节），以能稳定调用标定、正射 remap 与读写约定 XML 为准。

## 4. 功能 1：生成标定板打印文件

对等 C++ 门面：`bool cam::MakeBoard(const std::string& iniPath, std::string& errMsg)`。

### 4.1 行为

- 入参只有 ini 路径。版面参数全部来自 `[checkerboard]`：`square_mm`、`cols`、`rows`、`border_mm`、`paper_w_mm`、`paper_h_mm`、`out_dir`。
- 键缺失时使用与 C++ `CheckerboardConfig` 相同的缺省值（见第 6.1 节）。
- 先校验版面，再创建 `out_dir`（不存在则创建），再写三件产物。任一步失败则返回 false，并给出中文原因。
- 三个产物都成功写出才返回 true。

### 4.2 版面规则（与 C++ 现网几何等价，不要求 PDF 字节级一致）

- 图案在纸张内居中：横向偏移 `ox = (paper_w_mm - square_mm * cols) / 2`，纵向偏移 `oy = (paper_h_mm - square_mm * rows) / 2`。
- `ox`、`oy` 均不得小于 `border_mm`，否则判定留白不足。
- `square_mm`、纸张宽高必须为正，`cols`/`rows` 必须 ≥ 2，`border_mm` 不得为负。
- **横纵格数必须一奇一偶**（避免 180° 旋转歧义）。出厂默认 35×28 满足此约束。
- 黑格规则：在以纸张左下角为原点、单位为毫米的坐标系中，行 `r`、列 `c` 从图案左下角起算，当 `(r + c) % 2 == 0` 时为黑格。
- 方向标记：左上角白边内一根黑色细长条，宽 `0.6 * square_mm`、高 `0.15 * square_mm`，默认定位与 C++ 一致：`x = ox * 0.4`，`y = paper_h_mm - oy * 0.4 - mark_h`（原点在纸张左下角）。该标记用于辨识摆放方向，打印说明中须提示“请勿当作脏点修掉”。
- **标记不得与棋盘图案相交或压线**（两者都是轴对齐矩形，坐标系同上）。仅要求 `ox/oy ≥ border_mm` **不足以**防止合法配置下标记侵入棋盘。反例：`cols=35, rows=28, square_mm=15, paper=540×423 mm, border_mm=0` 时，`ox=7.5 mm`、`oy=1.5 mm`，当前留白校验通过，但标记会进入图案。出现相交时必须失败并给出第 9.2 节对应文案，不得直接画出侵入棋盘的标记。默认定位规则在留白足够时保持与 C++ 相同，不另改位置公式。

### 4.3 产物（均落在 `[checkerboard] out_dir`）

| 文件名 | 要求 |
|---|---|
| `checkerboard.pdf` | 矢量打印文件。页面尺寸等于 `paper_w_mm × paper_h_mm`（毫米按 `1 mm = 72/25.4 pt` 写入页面），必须能按 **100% 实际大小** 打印，边缘锐利。交打印店只打这一个文件。 |
| `checkerboard_preview.png` | 人工核对预览图，比例与版面一致（预览尺度与 C++ 相同：`4.0` 像素/毫米）。**不得用于打印。** |
| 打印说明文本 | **文件名为 `打印说明.txt`**。这是相对 C++ 现网 `Readme.txt`（见 `board_generator.cpp`）的有意差异，见第 11 节 D。正文按附录 A 生成（utf-8-sig）。附录 A 已纠正 C++ 模板的两处问题：应写居中后的**实际留白** `ox`/`oy`，而不是把最小留白 `border_mm` 写成四边边距；连续格验收在格数不足 10 时改用实际格数，不能再要求“条款永远不改”却与合法小棋盘冲突。 |

### 4.4 参数非法时必须失败的情况

- 格子边长或纸张尺寸非正，或横纵格数小于 2。
- 横向或纵向居中后的留白小于 `border_mm`。
- 方向标记矩形与棋盘图案矩形相交或压线（见第 4.2 节反例）。
- 横纵格数奇偶相同（例如 35×35）。
- 无法创建输出目录，或任一产物无法创建、写入、保存。

## 5. 功能 2：相机标定

对等 C++ 门面：

```text
bool cam::Calibrate(const vector<Image>& boardImages,
                    const string& iniPath,
                    CalibReport* report,
                    string& errMsg)
```

### 5.1 行为

- 传入 1～n 张采图。单张直接求解；多张视为**同一姿态下的连拍降噪**：连拍期间相机、镜头和标定板都必须保持静止，不能只写“固定机位”。各图角点取均值后再求解。空列表必须失败。
- 多张图尺寸必须一致；任一张角点检测失败则**整体失败**，并在错误信息中指明是第几张。
- `report` 可选：需要时返回机器可读摘要；不需要时可忽略。配置成功读出后即应填写 `xml_path`。失败时已知字段尽量填写；验证未完成时 `verify_mean_px` / `verify_p95_px` 为 0。
- 参数读 `[calibrate]`，并遵守与 `[checkerboard]` 的缺省跟随（见第 6.2 节）。
- 无论质量是否达标，只要求解并写出 XML 成功，文件都保留，并写入正式 `out_xml`（与 C++ 行为一致，见第 11 节 A）。**禁止现场在接口返回 `ok=false`（质量不达标）后启用该文件。** 调试开时 QA 图按第 5.5 节规则保留。质量不达标返回 false；对外最终 `err_msg` 以总质量门禁那一句为准，见第 9.3 节。

### 5.2 必须保持的求解与验证行为

这些行为直接影响标定文件与质量数字，属于需求约束，不在此指定代码结构：

- 角点：SB 棋盘格检测（对等 `findChessboardCornersSB`，含图像归一），检出数必须恰好等于 `pattern_cols × pattern_rows`；再做亚像素细化（窗口 21，终止条件对等 C++：EPS+MAX_ITER，30 次，精度 0.01）。
- 标定求解：单视图（均值角点作为一组观测）`calibrateCamera`，约束 **fx = fy**、**主点固定在图像中心**（对等 `CALIB_FIX_ASPECT_RATIO | CALIB_FIX_PRINCIPAL_POINT`）。只使用这两个约束标志，**不得**再启用 rational、thin-prism、tilted 或其它畸变模型。畸变固定为 5 项 `k1,k2,p1,p2,k3`，不得写出 8/12/14 项。
- 物点网格按 `square_x_mm`、`square_y_mm` 生成，单位毫米；外参平移单位为毫米。
- 写出 XML 后必须回读自检。
- **正射验证闭环**（功能 2 内部步骤，不是功能 3）：按第 5.8 节把代表图正射后，在校正图上重检角点并回到理想网格，统计平均残差与 p95 残差。多图时 QA 与验证均以**输入列表的第一张**为代表图（命令行则是按第 7.2 节排序后的第一张）；顺序变化可能改变均值角点和代表图，验收必须冻结顺序。
- RMS 分级日志（仅日志，不单独改变返回值）：≤ 0.1 px 记达标；0.1～0.3 px 记偏高警告；> 0.3 px 记超门禁警告。
- **RMS 超限后的控制流**必须与 C++ `FinishCalibrationAndQa` 一致：`SolveAndSaveCalibration` 在 RMS > 0.3 px 时会先给出中间态错误句并返回 false，但只要 XML 已写出，后续仍须继续回读 XML、在 debug 打开时生成 QA、做正射验证，再以总质量门禁句覆盖对外 `err_msg`。不得在 RMS 超限后提前结束而跳过验证。若求解硬失败（XML 未写出），则回读失败时对外透传求解阶段错误，不再做 QA 与验证。单独的“RMS … 超过 0.3 px 门禁（标定文件仍已写出…）”只作内部中间态，**不作验收对照**。

### 5.3 质量门禁

同时满足以下两项才返回 true（标定成功且质量达标）：

| 指标 | 门禁 | 说明 |
|---|---|---|
| RMS 重投影误差 | **≤ 0.3 px** | 超过则失败，但 XML 仍写出 |
| 正射验证闭环平均残差 mean | **≤ 0.5 px** | 超过或验证未通过则失败；验证未完成时该值按 0 填入 report，但不得当作达标 |

门禁数值与 C++ 现网一致，本阶段不调整阈值。验证门禁严格复刻 C++ 的像素门禁（mean ≤ 0.5 px），对拍时冻结 `target_mm_per_px=0.136`，不改为物理量门禁（第 11 节 C）。

注意：`verify_mean_mm = verify_mean_px × target_mm_per_px`。在缺省刻度 0.136 下，0.5 px 对应 0.068 mm，这只是像素门禁的物理含义说明，不是另一套验收门槛。对拍与验收仍以像素门禁为准，不得改刻度缺省，也不得只改门禁单位。

### 5.4 采图要求（写入文档与打印/操作说明，作为使用约束）

- 数量：建议 3～5 张连拍；单张可以求解；超过 5 张收益递减，不必作为强制上限。
- 连拍期间**相机、镜头和标定板都须保持静止**（同一姿态重复观测，不是换角度标定）；机位、镜头、分辨率还必须与后续正式使用（测量）完全一致。
- 标定板须吸风展平，与生产同光源、同工作距离；尽量充满画面，四周静区完整可见。
- 角点检出数必须恰好等于内角点数（出厂跟随制板：35×28 格 → **34×27** 内角点）。缺角或裁切导致检测失败。
- 打印后应用卡尺实测格距；与 `[checkerboard] square_mm` 有偏差时，回填 `[calibrate] square_x_mm` / `square_y_mm`。

### 5.5 产物

| 产物 | 路径 | 何时输出 |
|---|---|---|
| 标定文件 | `[calibrate] out_xml`（默认 `assets/calibration/checkerboard_calib.xml`） | 求解成功即写出，不受质量门禁与 debug 开关影响 |
| QA 质检图 | `[calibrate] qa_dir`（默认 `temp/calibration_qa`） | 仅当 `[debug] save_intermediate=true`。验证通过时为 4 张；正射重检失败时只落前 3 张，第 4 张可不生成，不是“只要 debug 打开就必有 4 张”。 |

QA 文件名与含义必须与 C++ 一致：

| 文件名 | 含义 | 何时写出 |
|---|---|---|
| `01_corners_overlay.bmp` | 角点检测叠加（多图时叠加均值角点） | debug 打开且已进入 QA 流程 |
| `02_residual_vectors.bmp` | 残差矢量（检测点指向模型投影点，矢量放大 50 倍） | 同上 |
| `03_rectified.bmp` | 正射校正图 | 正射图生成成功后 |
| `04_verify_grid.bmp` | 验证网格：理想网格空心绿圈，实测角点实心红点 | **仅当**正射图上角点重检成功并完成验证统计后 |

闭合规则（与基线 `FinishCalibrationAndQa` / `SaveImage` 对齐）：

- debug 打开且正射重检失败时：只落前 3 张（若当时已生成），**可以不生成**第 4 张；接口仍走到总门禁，对外 `err_msg` 中验证 mean 处写“未通过”。
- 创建 `qa_dir` 失败：接口失败，文案为第 9.3 节“创建 QA 目录失败”。
- 单张 QA 写盘失败：C++ 现网只记日志、**不因此让标定接口失败**；已写出的 XML 与已成功落盘的 QA 图保留，失败的那张可以缺失。本工程按此行为验收。
- 验收必须使用**全新空的** `qa_dir`（或先清空），避免目录里的旧图（尤其是上次留下的 `04_verify_grid.bmp`）被误判为本次产物。

### 5.6 标定 XML 字段（必须可被 OpenCV FileStorage 与现有 C++ 回读）

写出字段与 C++ `SaveCalibrationXml` 对齐：

| 字段 | 含义 |
|---|---|
| `camera_matrix` | 必须写成 **3×3** 矩阵（64 位浮点，fx = fy，主点为图像中心）。C++ `LoadCalibrationXml` 按 `rows==3 && cols==3` 校验，写成 9×1、1×9 或其它形状会回读失败，即使 9 个数本身正确也不行。 |
| `dist_coeffs` | 固定 5 项 `k1,k2,p1,p2,k3`（写出为 1×5；回读侧按元素总数为 5 校验）。不得启用 rational / thin-prism / tilted 等其它模型，也不得写出 8/12/14 项。 |
| `rvec` / `tvec` | 3 个元素（写出为 3×1），板面外参，tvec 单位 mm |
| `image_width` / `image_height` | 标定图像素尺寸 |
| `square_x_mm` / `square_y_mm` | 所用格距（毫米） |
| `pattern_cols` / `pattern_rows` | 内角点行列数 |
| `rms` | RMS 重投影误差（px） |
| `mm_per_px` | 正射刻度，来自 `target_mm_per_px` |
| `created` | 写出时的**本地时间**，格式必须为 `YYYY-MM-DDTHH:MM:SS`（对等 C++ `NowTimeString`：`strftime("%Y-%m-%dT%H:%M:%S")` + 本地时区）。不含时区后缀、毫秒，也不得写成 UTC/`Z`。 |

回读后须能做与 C++ 相同的完整性校验（`camera_matrix` 必须是 3×3；`dist_coeffs` 元素总数为 5；矩阵类型可归一到 64 位浮点）。该文件是与 C++ 测量工程衔接的正式产物，字段名、矩阵形状与数值语义不得自行改名、改形状或改单位。

### 5.7 标定摘要 `CalibReport`

| 字段 | 含义 |
|---|---|
| `rms` | RMS 重投影误差（px） |
| `verify_mean_px` | 正射验证闭环平均残差（px） |
| `verify_p95_px` | 正射验证闭环 p95 残差（px） |
| `xml_path` | 标定文件实际输出路径（配置解析后的绝对路径） |

### 5.8 正射变换约定（功能 2 内部，不是功能 3）

对等 C++ `Rectifier::Load` / `Rectify`。必须分清**输出像素尺寸**和**物理覆盖范围**：

- **输出像素尺寸**与标定输入图像相同（宽 `w`、高 `h`），**不**随 `target_mm_per_px` 改变。C++ 随包 ini 注释里“只影响输出图大小”的说法不准确，本工程不得再沿用。
- `target_mm_per_px`（记为 `s`）改变的是：每个输出像素对应的板面毫米数（px→mm 系数），以及输出画面所覆盖的板面范围。增大 `s` 会看向更广的板面（每像素代表更多毫米），减小 `s` 则相反；输出宽高像素数不变。
- **中心锚点**：以输入图像中心像素 `cx = (w-1)/2`、`cy = (h-1)/2` 反投影到板面 `z=0`，得到 `(Xc, Yc)`，作为输出图中心对应的板面毫米坐标。
- **方向判定**（防镜像）：将板面点 `(Xc,Yc)`、`(Xc+1,Yc)`、`(Xc,Yc+1)` 正投影回原图，得到 `p0,p1,p2`。`sign_x = (p1.x-p0.x) ≥ 0 ? +1 : -1`，`sign_y = (p2.y-p0.y) ≥ 0 ? +1 : -1`。若板面 X 轴在图像中更接近竖直（`|(p1.y-p0.y)| > |(p1.x-p0.x)|`），记警告、不失败。
- 输出像素 `(u,v)` 对应板面：`X = Xc + sign_x * (u-cx) * s`，`Y = Yc + sign_y * (v-cy) * s`，再经相机内参、5 项畸变与外参正投影回原图取色。
- **插值**：线性插值（对等 `cv::INTER_LINEAR`）。**边界填充**：常数 0（对等 `cv::BORDER_CONSTANT`，黑色）。
- **物理覆盖范围**：约 `(w-1)*s` 毫米 × `(h-1)*s` 毫米，中心在 `(Xc, Yc)`。

### 6.3 `[debug]` 通用开关

| 键 | 随包 ini 显式值 | 键缺失时的行为 |
|---|---|---|
| `save_intermediate` | `false`（部署模式，与当前 C++ 出厂 ini 一致） | 视为 `false`，不落 QA 图 |

- `true`：功能 2 按第 5.5 节向 `qa_dir` 写 QA 质检图。验证通过时为 4 张；正射重检失败时只落前 3 张，第 4 张可不生成。不要把本开关理解成“打开就必然有 4 张”。
- `false`：只保留最终标定 XML，不落过程图。
- 本开关不影响功能 1 的三件套（三件套始终写出）。
- 出厂 ini **仍显式写 `false`**，这一点与 C++ 现网 ini 一致，不得改成出厂为 `true`。
- 键缺失时，本工程约定为 `false`。这是相对 C++ 的有意差异：C++ `DebugConfig` 结构体缺省为 `true`，现场若漏写该键就会刷 QA 图。新工程不复制这个陷阱。

## 7. 接口与命令行

### 7.1 Python 门面（命名可在设计阶段微调，语义必须对等）

- `version() -> str`：门面版本串。Python 工程自有版本，不要求与 C++ 的 `2.1.4` 相同，但须可查询。
- `make_board(ini_path) -> (ok: bool, err_msg: str)`
- `calibrate(board_images, ini_path, report=None) -> (ok: bool, err_msg: str, report)`  
  `board_images` 为 1～n 张图像（内存图像对象，如 OpenCV 数组）；`report` 为第 5.7 节摘要。

调用约定：成功时 `ok is True` 且 `err_msg` 为空（或可忽略）；失败时 `ok is False` 且 `err_msg` 为第 9 节中文原因。不抛异常。

### 7.2 命令行（现场与验收使用）

至少提供两条可独立执行的命令（具体子命令名由设计确定）：

1. **制板**：传入 ini 路径，在 `out_dir` 生成三件套，进程退出码 0 表示成功，非 0 表示失败并在控制台打印中文原因。
2. **标定**：传入 ini 路径；图像默认读 `[calibrate] input_dir`，也允许显式传入 1～n 个图像路径。成功且达标退出码 0；失败非 0，并打印中文原因与（若已写出）XML / QA 路径。控制台应打印 RMS、验证 mean / p95，便于现场判断。

命令行读 `input_dir` 时，行为与 C++ `common::ListImages` + `RunCalibrateFromDir` 对齐：

- 扩展名（大小写不敏感）：`.bmp`、`.png`、`.jpg`、`.jpeg`、`.tif`、`.tiff`。
- **不递归**子目录，只扫该目录一层。
- 文件名（不含扩展名）包含 `demo`（不区分大小写）或 `副本` 的条目跳过。
- 其余命中文件按**完整路径字符串字典序**排序（同一目录下即按文件名排序）。排序后的第一张用于 QA 与正射验证；多图角点均值也依赖该顺序，顺序变化可能影响结果，验收必须冻结顺序。
- 某一张读失败：整次命令行标定失败，打印中文“图像读取失败: {path}”，不跳过坏图继续，也不对已读入的子集求解。
- 目录不存在或过滤后无图：不进入标定，给出中文提示。

不要求、也不应提供功能 3 的批量测量入口。

占位符：`{ox}` / `{oy}` 为居中后的实际留白，`ox = (paper_w_mm - square_mm * cols) / 2`，`oy` 同理，不是 `border_mm`。`{nx} = min(10, cols)`，`{ny} = min(10, rows)`，`{span_x} = nx × square_mm`，`{span_y} = ny × square_mm`。第 3 款：当 `nx` 与 `ny` 相同，直接比较两条实测跨距，差不超过 0.3 mm；当格数不同，先各自除以所用格数得到单格边长再比，差不超过 0.03 mm（与 10 格差 0.3 mm 等价）。
